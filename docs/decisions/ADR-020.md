# ADR-020: catalog@2 and open-default@2: what goes in, how each version is kept, and what stays on catalog@1

Status: accepted on 2026-11-21. Proposed the same day by the std track,
work package catalog@2, phase 1; the owner answered its five questions
the same day (see "The owner's answer" at the end): A to questions 1, 2,
3 and 5, B to question 4. Question 4 moves the slice to version 2 in this
package; decision 8 and the consequences are amended for it, and the
proposed text stays above the amendment. It adds two files to
`standard/schemas/` and changes none, and it changes the reading of
PLAN.md section 5.1 in one field (decision 2). `catalog@1` and
`open-default@1` do not change by one byte.

## Decisions (proposed)

1. **Two parts, one version.** The work package has two parts, each with
   its own gate, review and merge (rules R7 and R9):
   - catalog-2a, the structure: decisions 2 to 6, with a `catalog@2` and
     an `open-default@2` whose content is that of version 1 with the
     defaults moved (no meaning changes);
   - catalog-2b, the content: decision 7.

   On `main` between the two, both are marked `draft` (decision 3): no
   kit, task, run or score may name a draft version, and a gate check
   says so. `catalog@2` and `open-default@2` are frozen and tagged when
   catalog-2b merges after its gate and its review.

2. **Defaults move to the house (#28, item 1).**
   - An entry of `catalog@2` has no `house_default`. The house
     `open-default@2` holds them in `defaults.yaml`: per entry, or per
     (entry, unit) for an entry with `units`, the alternative (null: no
     default, a person is asked), its slot values (these replace
     `default_values` of `house.yaml`), the public source of the choice,
     and optionally `when`: a predicate over the design features of the
     catalog, the first that holds wins. `when` carries #2 (a default by
     design) and nothing else in this version.
   - The decision-record class `house_default` keeps its name and its
     meaning ("the information lives in the house standard"); only the
     entry field moves. No decision record changes shape.
   - `catalog@1` and `open-default@1` keep the old shape. The loader
     reads the shape the catalog names (decision 6). The call sites of
     the defaults are few (`houses.default_value`, `Entry.house_default`
     in checks, overview and catalog).
   - PLAN.md section 5.1 shows `house_default` in the example entry. From
     `catalog@2` that line is read as a field of the house's
     `defaults.yaml`; the example gets one comment line saying so
     (ADR-020). Nothing else of the plan changes.

3. **Each version is a frozen folder, and stays loadable.**
   - `standard/catalog/` is renamed `standard/catalog@1/` (`git mv`,
     bytes unchanged) and `standard/catalog@2/` is added beside it.
     `standard/houses/open-default@1/` stays; `open-default@2/` is added.
     The names follow the tag and the houses.
   - `standard/versions.yaml` lists every version with its status
     (`draft` or `frozen`), the date, the ADR or the owner's answer that
     froze it, and the git tree hash of its folder. `catalog@1`: frozen
     2026-11-17, ADR-004, tree `a25d42c0`. `open-default@1`: frozen
     2026-11-17 with `catalog@1` (accepted at N1, unchanged since; this
     ADR records the freeze), tree `7ac0f4fc`.
   - The gate check "frozen" computes the tree hash of each frozen
     folder in Python, by git's own tree format, without calling git (it
     works in any clone and under WSL), and compares. Plants (rule R5):
     one byte changed in a file of `catalog@1`; a file added to
     `open-default@1`; a draft version named by a kit.
   - Every command and function that loads a catalog or a house takes a
     label (`--catalog catalog@N`, `--house open-default@N`). A house
     names the catalog version it needs, and a pair that does not fit is
     refused. The default pair stays (`catalog@1`, `open-default@1`)
     until a later part moves the slice (decision 8). A task folder still
     copies the catalog to `standard/catalog/` inside the task, so its
     bytes do not depend on the folder's new name.
   - The tag `catalog@1` stays. The tags `catalog@2` and `open-default@2`
     are set at the freeze.

4. **Version rules (#28, item 2).**
   - Any change of a file in a frozen folder is a new version, numbered
     by an integer. There are no minor versions; the migration file says
     instead what a step keeps.
   - `standard/catalog@2/migration.yaml` lists, from `catalog@1`, every
     (entry, alternative) and every (entry, unit) that is added, removed
     (with its replacement, or none), renamed, or changed in meaning.
     Each line names its backlog record (decision 5).
   - The meaning of an alternative is the SHA-256, in canonical JSON, of
     its question, statement template, definition, the entry's notes and
     fixed rules, its slot declarations and the bytes of its compile
     template. The gate check "migration" computes it for both versions:
     every difference has exactly one line, every line is a real
     difference, and every line names a backlog record accepted for the
     version. Plants: a definition changed without a line; a line for an
     alternative that did not change; a line with no accepted record.
   - A decision record of `catalog@1` maps to `catalog@2` through the
     file (kept, renamed: the new ID; changed or removed: flagged for a
     person). A function does it, with tests; nothing in M1 migrates
     records yet.
   - A house version steps on any change of `defaults.yaml`, `house.yaml`,
     a parent spec, a template or STANDARD.md, and names the catalog
     version it needs.
   - Scores are compared within one pair (catalog, house). Two pairs are
     comparable on a kit only when every decision of the kit is kept by
     both migration files; a script decides it, and a report names its
     pair.

5. **The backlog as a file (#28, items 3 to 5).** `standard/BACKLOG.yaml`
   holds one record per proposed change of the standard: an ID, the
   issue, the layer (`catalog`, `house`, `schema`, `docs`, `code`), the
   target (an entry, an alternative, a default, a file), the kind, the
   status (`open`, `accepted: <version>`, `done: <version>`,
   `waits: <where>`, `rejected`), the reason, the ADR. It starts with the
   two tables of decision 7, one record per item. `specfirst status`
   prints what is open and what waits, by layer. A freeze is a status in
   `versions.yaml` with its date and reason (item 4). The layers of #1 to
   #25 are taken from each issue's text, not its title (#28, item 5).

6. **Schemas.** No file of `standard/schemas/` changes:
   `decision-record.schema.json` is bound by bytes to the kept run, and
   `catalog-entry.schema.json` (version 0) stays the schema of
   `catalog@1`. Two files are added, each with its examples:
   - `catalog-entry.v1.schema.json` (`specfirst:schemas/1/catalog-entry`):
     version 0 without `house_default`; with `fixed_rules` (a list of
     `{id, text, sources}`, #4 and #18); with an optional `evidence`
     (`cited`, `read` or `probed`) on each citation (#20); and with
     optional `sources` on an alternative, printed in STANDARD.md (#15,
     #20). `catalog.yaml` of `catalog@2` names its entry schema and holds
     the list of defined terms (#18).
   - `house-defaults.schema.json` (version 0): the shape of
     `defaults.yaml`.

   The directives of the compile templates get a closed list of `$fn`
   names, checked in code with a plant (#20); that is not a schema.

same labels.

## Alternatives

- **In place.** `catalog@2` replaces the files of `standard/catalog/`,
  and `catalog@1` stays reachable by its tag only. Simpler, but the two
  cannot be loaded side by side, and the slice moves at once: the kept
  run goes stale, HAND01 and the natural-form texts are redone, with
  their model costs, in this package.
- **No rename**: `standard/catalog/` stays `catalog@1` and
  `standard/catalog@2/` is added. Less to change in code and docs; two
  naming rules side by side. Not taken.
- **Defaults stay in the entries** (#28 not taken). Every default change
  is then a catalog version, a second house (M2) needs a copy of the
  catalog, and the owner's choices on defaults freeze the alternatives
  beside them.
- **Major and minor versions** (#28 as written). A number chosen by hand
  can be wrong; here the step is an integer and what it keeps is computed
  (rule R1).
- **One part instead of two.** One review of everything at once; a fault
  of the structure would be found only after the content is written.
- **The record schema in this package too** (#19, #20). It changes every
  record and the bytes the kept run is bound to, and std-2 owns it.

1. **Scope.** Version 2 takes the review's fixes as in decision 7 (#1 to

5. **Structure and freeze** (#28): defaults move from the catalog into

### Amendment of decision 8 (question 4, answer B)

Decision 8 as proposed is replaced by this:

8. **The slice moves to version 2, last.** A third part, catalog-2c,
   moves the slice of ADR-005 from (`catalog@1`, `open-default@1`) to
   (`catalog@2`, `open-default@2`) after catalog-2b has merged and
   version 2 is frozen: the default pair of every loader, the generator
   and the kits of every gate seed, the natural-form texts of the
   statements of the slice that change (written by a model in the loop of
   ADR-009, accepted into the append-only store, never by a gate), probe
   recipes for the new alternatives of the slice's units (#5, #10, #13,
   #24), HAND01's table worked out again, the reader's task folders, and
   one new kept dry run of arm R in place of `R-task-04119188ff71`.
   `catalog@1` and `open-default@1` stay frozen and loadable by label;
   nothing names them by default after catalog-2c.

Until catalog-2c merges, decision 8 as proposed holds: catalog-2a and
catalog-2b leave the slice on version 1, and the consequences above hold
for them. For catalog-2c the consequences change: the generated kits and
the reader's task folders get new bytes, the kept run is replaced by the
new one (its binding names `catalog@2` and `open-default@2`), and the
gates gen-2a, gen-3a, read-1a and read-2a are run on clean clones with
their new expected values, each difference stated in the report.

## Carried out

### catalog-2a (the structure)

What the decisions above left to the work, and how it was settled:

- `standard/versions.yaml` lists `catalogs` and `houses` by label, each
  with `status`, `date`, `by` (what froze it) and, when frozen, `tree`; a
  house also names its `catalog`. The default pair is a constant of
  `specfirst.compile.versions` (`DEFAULT_CATALOG`, `DEFAULT_HOUSE`), and the
  check "frozen" fails when it names a draft.
- The tree hash counts every file as a regular file (mode 100644): a frozen
  folder of the standard holds no script and no link, and the mode bit
  cannot be read on a Windows drive under WSL. A unit test holds the
  function against `git write-tree` on a small folder; the check holds it
  against the recorded trees, which are those of the tag.
- A kit's labels come from its `kit.yaml` (`catalog: {name, version}`,
  `house`). The generator and the task builder refuse a draft label; the
  check "frozen" reads every `kits/*/kit.yaml` of the repository. A task
  copies the catalog version its kit names into `standard/catalog/` of the
  task folder.
- `defaults.yaml` holds `house`, `catalog` and `defaults`; a default is
  `{rule, values, sources}` or `{cases: [...]}`, and an entry with `units`
  has one under `units`. `house.yaml` of `open-default@2` names
  `catalog_version: 2` and `defaults: defaults.yaml`; `default_values` is
  gone. A default by design is resolved from the design features; without
  them it is left out of a list of defaults and refused for one decision.
- A backlog record has `status` (`open`, `accepted`, `done`, `waits`,
  `rejected`) and beside it `version` (accepted, done) or `for` (waits),
  in place of the combined `accepted: <version>` of decision 5.
- The meaning of an alternative also includes the entry's `applies_when`;
  its fragment of the compile template is the parsed fragment, not the
  bytes of the whole template file, so that a change of one alternative's
  fragment is a change of that alternative only.
- `specfirst house --write` refuses a frozen house. `--house` without
  `--catalog` takes the catalog version the house needs.
- After the review of catalog-2a (pass 1): the trees of the frozen
  versions are pinned in code as well (`versions.PINNED`), so that a frozen
  folder changed together with its line of versions.yaml still fails; a
  freeze adds its line. A version's files must say the version its folder
  names, and a house the catalog that versions.yaml pairs it with. The tree
  hash does not see a change of a file's mode only; git's diff and the
  review do.
- The commands of the generator, the reader harness and the scorer take
  the default pair: what they write names its pair (a kit's `kit.yaml`, a
  task's catalog), and a task reads the catalog its kit names. They get no
  `--catalog` or `--house`, which would let a kit be built from a pair the
  slice was not written for. catalog-2c moves the default pair, and with it
  the rendering of the reader's skills (`harness/knowledge.py` reads the
  defaults of the catalog, which version 2 no longer holds).
- The script of decision 4 that says whether scores stay comparable is
  `migration.comparable`: every decision of the kit kept, or renamed
  without a change of meaning.

# ADR-019: P4 on a reference study: one class per decision instead of a failure

Status: decided in the work on issue #30 (track gen), 2026-11-21, by the
executor. The independent review (docs/reports/issue-30.review.md) signed
it with six findings, none blocking. PLAN.md, `standard/schemas/` (the decision record included),
the catalog `catalog@1`, the house standard `open-default@1`, the method
registry, the generator (`GENERATOR` is unchanged) and every file of a
generated kit are not changed. The decisions stand unless the owner
objects. The points for the owner are listed at the end; none blocks.

## Context

PLAN.md section 4.6 states P4: "Changing any decision to another listed
alternative changes at least one result", tested by mutation. On a
generated study that is right: the probes are planted so that the
alternatives separate, and the gate of gen-2a asks it of every decision
that a kit's log of probes claims (ADR-007, decision 6;
`specfirst.gen.verify.mutate`).

On a reference (a study that was really delivered, or any study used as an
anchor: tier C) the data were not made for the decisions (issue #30):

- a window value: several values give the same flags, because no event
  falls between them;
- two end rules give other flags in ADaM and the same cells in the table,
  because the records that differ are outside the table's subset;
- a rule whose column no output reads can never separate.

Strictly read, P4 fails on such a study; read loosely, a decision that was
only reproduced looks proven. Section 4.7 already says what to do: "Where
data cannot separate two alternatives, the decision is marked
`unseparated` and reported. It is not counted as proven." The issue asks
which kind of "not separated" each decision is, so that a person knows
what to ask, and for a numeric parameter the interval that reproduces.

Nothing in the repository mutated a reference before. std-2 ("the mutation
runner and the identifiability matrix, on the pilot") has not started. The
scorer's `scorer.separation` (read-1a) mutates the hand-made study HAND01
and counts wrong cells; it does not look at ADaM or at the ARD, and it
scans no numeric slot.

## Does this stay within PLAN.md?

Yes, as decided here.

- P4 as stated stays the requirement for generated studies. Their matrix,
  their gate and their files do not change.
- On a reference, section 4.7 is the rule that applies. The classes below
  say which kind of `unseparated` a decision is; they are recorded in the
  identifiability matrix of the reference, which has no schema of its own
  (PLAN.md section 8 names the file `identifiability.json`, not its form).
- The decision record keeps its schema. Its field `identifiable` has two
  values (`separated`, `unseparated`), and a decision is `separated` there
  only when its class is `separated` (decision 4).

A schema change (a field `identifiable` with four values) would have
needed an ADR approved by the owner; it is not made, and is item 1 of
"For the owner".

## Decisions

1. **What one other value does: the highest layer at which two builds
   differ.** A decision is built at its value in the study (gold) and at
   every other value tried, all other decisions kept, by the chain the
   scorer uses (`specfirst.score.candidate.Machine`: compile, yamaa, the
   Python result engine, the grids of layout draft 0). The two builds get
   one level (`specfirst.machine.separation.compare`):

   | Level | The other value |
   | --- | --- |
   | `fails` | cannot be built on these data, or compiled with the other decisions |
   | `outputs` | changes a printed cell, a row label, a column label, a title or a footnote, or builds an output that gold does not (or not one that gold does) |
   | `results` | changes an ARD row, and no printed cell |
   | `adam` | changes an ADaM cell, and no ARD row |
   | `none` | gives the same ADaM datasets, ARD and outputs |

   `fails` and `outputs` separate. The reference of a real study is what it
   prints (a CSR table, the formatted values of an ARS file; P2 compares
   grid text), and the matrix of a generated kit compares grids too
   (gen-2a). An ARD row that no cell prints is "at the level of a
   dataset": the ARD is the analysis results data. Not chosen: ARD as the
   line of separation, as the test column of section 4.6 reads ("diff the
   ARD"). On a reference it would call a value separated that the printed
   reference cannot tell from gold (item 2 of "For the owner").

2. **The values tried.** Every alternative of the catalog entry with the
   examples of its slots, and every list of the gold value with one item
   left out (`compiler.other_values`, what the compile check proves the
   binds against). For every integer slot of the gold alternative
   (`ae.teae.end` days, the decimals of `tfl.decimals.rule`, the count of
   `demo.race.pooling`), the values next to gold, one at a time, down and
   up, until a value separates in the outputs or the scan ends: at the
   bound of the slot in the catalog, or 30 steps from gold (`--span`).
   Not scanned: number slots (no step), lists, the slots of alternatives
   other than gold's.

3. **The class of a decision, from all its values**
   (`separation.classify`):

   | Class | When | Review |
   | --- | --- | --- |
   | `inert` | no value tried changes an element that an output reads | not asked |
   | `separated` | every value tried separates in the outputs | not asked |
   | `unseparated` | some value tried has level `none`: nothing in the study can tell it from gold | asked first, with the values that reproduce and the interval |
   | `separated_at_dataset_only` | no value has level `none`, and some have `results` or `adam` | asked, with the outputs that read the decision named |

   `no_alternative` (nothing to change to) is not a class. A decision is
   `separated` only when every other value separates: one value that
   reproduces the outputs leaves the gold value unproven, whatever the
   others do. This is how the matrix of a generated kit reads "separated"
   (every pair of the gold value with another alternative), and the
   stricter of the two readings of the issue's table ("an alternative
   changes the reference"); with the looser one a window that four values
   reproduce would be "separated" because a window of 7 days is not.

   What an output reads is static (`specfirst.gen.separate.reach`): the
   analyses behind its cells, their sets, subsets, groupings and methods,
   the output in the ARS file, every part of its layout, the ADaM columns
   these analyses read and, through the `derives_from` edges and the
   working columns of the resolved specs, every column they come from. A
   value is read when an element it changes in the compile
   (`candidate.element_changes`) is in that set for gold's build or for its
   own, or when it decides whether an output is built. An inert decision
   whose value nevertheless changes an output is a problem of the matrix
   (the reach missed what the output reads), never a class.

4. **The decision record and the scoring rule.** `identifiable` =
   `separated` for the class `separated`, `unseparated` for the three
   others, empty for `no_alternative` (`separation.identifiable`;
   `separation.credited` says whether results can confirm a decision). A
   scorer that reads `identifiable` compares the values of every decision
   of another class and reports it apart (sections 4.7 and 9.3), as it does
   today for the generated kits. That is the part of the scoring rule that
   is the machine's. What the scorer itself must do (an exam never credits
   an `unseparated` decision as learned; the report lists the classes
   apart, `unseparated` first) is the read track's, in
   docs/state/gen.md, "For the read track".

5. **The interval** (`separation.interval`). For an integer slot of the
   gold alternative: the run of values around gold that give the same
   outputs as gold, all other slots at gold. Each end says what stops it:
   a value that separates (`separated`), the bound of the slot
   (`slot_minimum`, `slot_maximum`), or the end of the scan (`scan_limit`:
   the interval may go on). The values inside that give the same build in
   all layers (`same`) and those that differ in a dataset only
   (`dataset_only`) are listed apart.

6. **The review** (`separation.review`): `unseparated` first, then
   `separated_at_dataset_only`, `separated`, `inert`, `no_alternative`;
   each with what to ask.

7. **Where it lives.** The classes, the comparison, the interval, the
   review and the comparison of two matrices: `specfirst.machine.separation`
   (no builds, no I/O). The builds and the matrix:
   `specfirst.gen.separate`. The test study of the acceptance:
   `specfirst.gen.sep01`. The command: `specfirst gen separate
   sep01|cdiscpilot01 [--vector house|window] [--span N] [--out FILE]
   [--check FILE]`; a matrix is written under build/separation/ (ignored),
   and `--check` holds a written matrix against a new mutation. Reused
   (rule R2): the scorer's chain (`score.candidate.Machine`,
   `element_changes`), the compiler's `other_values` and `base_vector`.
   Nothing of the read track or of the real track is edited.

8. **The test study SEP01** (the acceptance of issue #30). One dataset,
   nine subjects, the columns of `specfirst.compile.tiny`. It states two
   decisions (a window of 35 days; related is POSSIBLE or PROBABLE) and
   takes the house for the rest. Every value from 35 to 38 days reproduces
   the window, 34 and 39 separate; the origin of the study day changes the
   study day of ADVS and no output reads it (inert); the imputation of a
   partial start date changes the start date and the flag of one event,
   and its subject is in the table by another event (separated at dataset
   level only). The class of every decision of the slice is what mutation
   gives (`sep01.CLASSES`), held by tests/unit/test_separation.py.

9. **Planted defects (rule R5).** Each makes the check of one class fail
   (`sep01.check`, `separation.problems`): L4 dosed as randomized
   (`pop.safety.grouping` is then not `separated`); an event 36 days after
   a last dose (no other window reproduces: the window is `separated` and
   its interval is 35 to 35); L3's dizziness with a full date (the
   imputation is then `unseparated`, not `separated_at_dataset_only`); a
   reach that names nothing (every decision looks `inert`, and the window's
   values that change the table are problems). A written matrix with one
   class and one interval changed differs from a new mutation in exactly
   those two.

10. **The pilot, report only** (PLAN.md section 6.1: nothing is tuned on
    the pilot). The SDTM files that kits/cdiscpilot01 pins, read from the
    fetch cache after their SHA-256 is checked; the arms from DM and EX in
    the order of their highest dose (the high dose is titrated, 54 and then
    81 mg; the screen failures have no exposure). Two vectors: `house`, the
    house standard alone for the adverse event summary (the vector of arm
    S of read-1a's pilot report), and `window`, the same with a window of
    30 days, to show an interval on real data. Neither is the pilot's own
    rule set: expressing that as decision records is std-2's. The 18
    custom decisions of the efficacy tables (kits/cdiscpilot01/gold/
    decisions/) have no listed alternative and no compiler; P4 has nothing
    to change in them, and they are not in the matrix.

## Consequences

- A reference can be put through P4 without failing it, and every decision
  comes out with one class, what reproduces it and what to ask.
- The matrix of a generated kit is not this matrix. Its `unseparated` with
  the reason "the output does not read what the decision sets" is
  `inert` here; its other `unseparated` is `unseparated` or
  `separated_at_dataset_only` here (the kit's matrix does not compare
  ADaM). Putting the classes into the kits changes the bytes of every kit
  and the kept dry run of read-2a (ADR-017): not done.
- The values tried are the catalog's examples. An example that names
  nothing in the study can reproduce gold for that reason alone: on SEP01
  the total over the arms but the control "Active Control" is the total
  over all arms, because no arm has that name, and `tfl.columns.total` is
  `unseparated`. A person reads the value that reproduces before asking.
- The scan is one slot at a time, around gold; two slots that move
  together, or a value of another alternative's slot, are not scanned.
- An ARD row is identified with its grouping. A value that groups by
  another variable with the same values (planned and actual treatment the
  same for every subject) changes every ARD row and no printed cell, and
  is `separated_at_dataset_only` (the planted defect against `separated`
  shows it).
- The arms of the study are given once, for every value: a value that
  names the arms otherwise (a decoding map of `trt.planned.source` with
  labels of its own) is built with the same arms. A generated kit takes
  them from its design for each vector (`gold.arms_of`); a reference has
  no design model.

## For the owner (none blocks)

1. Whether the decision record should carry the class itself
   (`identifiable` with four values, or a field beside it): a change of
   `standard/schemas/decision-record.schema.json`, an ADR of its own.
2. Whether "separated" on a reference is read at the printed outputs (as
   here and in the matrix of a generated kit) or at the ARD (the test
   column of section 4.6). Two cases of the review (F2, F3) belong here:
   a value that the machine cannot build for a reason of its own counts
   as a separation today (on SEP01 and the pilot every failure is the
   data's), and an ARD row that differs only in the grouping it names
   counts as a changed result.
3. Whether std-2's matrix of the pilot (section 13.4) should take these
   classes; std-2 has not started.

# ADR-000: Bootstrap choices of base-0

Status: proposed, 2026-11-11. Items 1 and 2 were decided by the owner in the
base-0 session. Items 3 to 7 are the executor's choices where PLAN.md is
silent; they stand unless the owner objects. Numbers ADR-001 to ADR-003 are
reserved by PLAN.md for real-1 to real-3.

## Context

PLAN.md fixes what base-0 delivers (section 13.2) and leaves some of the how
open. The machine base-0 ran on also differed from the plan's assumptions:
the session ran in the Claude desktop app on Windows, in a folder that holds
the plan next to a `reference/` folder with employer material, and WSL had
no Linux distribution.

## Decisions

1. Repository location (owner). The repository is its own folder,
   `D:\trial_work\specfirst`, next to `reference/` and not above it. The
   plan asked for a folder that holds no employer material; this one holds
   none. `reference/` is denied in `.claude/settings.json` of the repository
   and of the parent folder, and `/reference/` is in `.gitignore`.

2. Linux environment (owner). Ubuntu 24.04 in WSL2, as decision 15 of the
   plan says. The alternatives were a Docker container and Windows-native
   tools.

3. One git per checkout. The checkout is on a Windows drive and is used by
   Windows-hosted sessions, so Windows git owns it and its worktrees. Linux
   git is used inside the fetch cache and for clean clones only. Reason: a
   worktree records absolute paths in the form of the git that made it.
   `.gitattributes` keeps all text LF.

4. Where the environment lives. `scripts/env.sh` puts the Python
   environment, the R library and the fetch cache inside the checkout by
   default, and under `~/.local/share/specfirst` when the checkout is on a
   Windows drive under WSL. Reason: the Windows mount is slow and has no
   symbolic links. A clean clone on the Linux file system gets everything
   fresh, which is what the gate needs.

5. How versions are pinned (rule R3).
   - Python: `env/requirements.lock`, exact versions with hashes, written
     by uv, installed with `pip --require-hashes --only-binary=:all:`.
   - R: R itself from the Ubuntu 24.04 archive; every package, the
     recommended ones included, from one dated snapshot of the Posit Public
     Package Manager (`env/r-repo.txt`), with the resulting versions in
     `env/r-packages.lock`. Reuse before build (R2): renv was the
     alternative; the snapshot gives the same pin with no project library
     machinery.
   - Sources: `third_party/sources.yaml`, fetched at the exact commit;
     single files by SHA-256.
   - System packages: recorded in `env/system.lock` for information only,
     because the Ubuntu archive does not keep old versions.

6. Evidence tests keep the spikes. The seven scripts in `evidence/` are run
   unchanged, as subprocesses, by `tests/evidence/`; the tests check what
   they print. Reason: the scripts are the evidence of section 3, and
   real-2 and real-4 replace them anyway. The checks on the printed text
   have their own planted-defect tests (R5).

7. Shared formats, version 0 (`standard/schemas/`). Where the plan gives
   fields, the schemas take them as written (sections 4.1 to 4.3, 7.2, 7.4,
   7.5). Choices the plan does not make:
   - An element ID is a layer prefix, a colon, and printable ASCII with no
     spaces. A writer must encode group values that contain spaces.
   - Decisions are graph nodes with the prefix `decision:` and the layer
     `decision`.
   - An ARD row stores `raw_value` as a JSON number or null, and the hash
     of the method options as `method_options_hash`.
   - A grid lists its data columns; row labels are not a column. A cell
     names its column and lists the IDs of its ARD rows, possibly none.
   - A graph edge has a `proof` field: `executed`, `static` or `judged`.
     Only `cites` is judged, and the schema rejects a `cites` edge with any
     other proof, so a judged edge cannot be presented as proven (section
     4.2). The schema also fixes the layers each edge type may connect.
   - A stated or default decision must carry a value and a citation.

## Not done in base-0

- No container definition in `env/` yet. Section 12 lists one; section 11.2
  needs it in M2. It could not be tested in this session.
- Schemas for the catalog entry, the kit and the method registry: std-1 and
  real-2 own them.

## Consequences

- Sessions hosted on Windows run Linux commands through
  `wsl -d Ubuntu-24.04 -- bash -lc "cd /mnt/d/trial_work/specfirst && ..."`.
- Any change to a version 0 schema needs a new ADR (section 13.2).
- If the owner moves the project into the Linux file system later, a fresh
  clone from `origin` is enough; nothing depends on the Windows path.

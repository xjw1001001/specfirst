# Lessons

Each failure once, with the check that now catches it (PLAN.md section 2.4).

| # | Found in | What went wrong, or would have | The check that catches it |
| --- | --- | --- | --- |
| 1 | base-0 | The machine had no WSL Linux distribution, only Docker Desktop's internal one, although the plan assumes WSL2. | `specfirst doctor` fails when Python, R or poppler is missing. The owner chose to install Ubuntu 24.04 (ADR-000). |
| 2 | base-0 | Git for Windows sets `core.autocrlf=true` system-wide. A checkout would get CRLF line endings, which breaks shell scripts and changes file hashes under Linux. | `.gitattributes` forces LF; `tests/unit/test_layout.py::test_text_files_have_lf_endings` fails on any CR in a maintained file. |
| 3 | base-0 | The `pdftotext` on the Windows path is Xpdf 4.00 from Git for Windows, not poppler. The CSR parsers were written against poppler 24.02 layout output. | `specfirst doctor` fails when `pdftotext -v` does not name poppler. Seen for real: with Xpdf's text the E27 test fails on its counts. |
| 4 | base-0 | The folder the session started in also holds `reference/` (employer material). A repository rooted there could have committed it. | The repository is a separate folder; `/reference/` is in `.gitignore`; `.claude/settings.json` denies reading it; `tests/unit/test_layout.py` checks both. |
| 5 | base-0 | The yamaa run of E1 writes `<dataset>-yamaa.parquet` into the data folder of the clone. | The E1 test works on a copy; `specfirst fetch --verify` fails when a cached source is not clean (`tests/unit/test_fetch.py`). See lesson 9 for the hole this check first had. |
| 6 | base-0 | R fills `R_LIBS_USER` with its own default when the variable is unset. A script that trusted it would have installed into, and listed, the user's personal R library. | The R scripts read `SPECFIRST_R_LIBS`, stop when it is unset, and use `.libPaths(lib, include.site = FALSE)`, so only the locked library and base R can be loaded. |
| 7 | base-0 | Ubuntu 24.04 ships R 4.3.3. In the CRAN snapshot of 2026-11-10 `car` needs `Deriv` (through `pbkrtest` and `doBy`), which needs R 4.5 or later; the snapshot's MASS, Matrix and mgcv could not be installed on R 4.3.3 either. | R 4.6.2 is installed from CRAN's Ubuntu repository at the exact version of `env/r-version.txt`; recommended packages come with R and are pinned in `env/system.lock`. `env/install_r.R` stops with the names of packages that the installed R cannot use, and `specfirst doctor` fails when R is not the pinned version. |
| 8 | base-0 review | A track worktree made by Windows git names its git folder by a Windows path. Under WSL, Linux git cannot open it, so the ASCII check, two unit tests, the commit line of a gate and the clean-clone script all failed in a worktree. The first test only covered a worktree made and read by the same git. | `specfirst.paths.git_env` translates the link; `tests/unit/test_checkout_git.py` plants a Windows-style link and shows both the failure without the translation and the fix. |
| 9 | base-0 review | `git status --porcelain` hides ignored files, and Pilot 7 itself ignores `*-yamaa.parquet`. So `specfirst fetch --verify` did not see the very leftover that lesson 5 names, and the planted-defect test passed only because its test source had no such ignore rule. | The status call lists ignored files too; `tests/unit/test_fetch.py::test_output_that_the_source_itself_ignores_fails` uses a source with that ignore rule and first shows that plain status sees nothing. A planted defect must be the real case, not a simpler cousin. |
| 10 | real-1 | The first build of the pilot kit did not finish in 10 minutes. The runner made every path of a resolution relative with `Path.resolve()`, once per origin: about 27,000 file-system calls on a Windows drive under WSL. On the Linux file system the same code took seconds, so the exploration had not shown it. | The runner resolves each distinct file once; `tests/unit/test_build.py::test_relocating_a_resolution_asks_the_file_system_once_per_file` counts the calls. Each gate check prints its seconds. |
| 11 | real-1 | The E1 spike's comparison would have passed three kinds of difference: NaN against a number, a column the reference does not have, and another column order. A spike's checker had been trusted without planted defects. | `tests/unit/test_compare.py` plants each one; `specfirst.machine.compare` counts or fails them. On the pilot the count is unchanged: 9,119,605 cells, 0 mismatches. |
| 12 | real-1 | Code adapted from an MIT source needs that source's copyright notice and license text kept with it, not only a line in SOURCES.md. | `tests/unit/test_sources.py::test_adapted_code_names_its_source_and_carries_its_license` fails when a row of adapted code has no license file, or the code does not name it. That test reads the rows that are there: the review found a second adapted function that had no row (lesson 14). |
| 13 | real-1 | Importing Pilot 7's Python code from the fetch cache, to compare our lineage with theirs, left a `__pycache__` folder in the cache. The next gate failed at its pins check, and so would any other session that shares the cache. | `specfirst fetch --verify` saw it (lessons 5 and 9). The test now imports with `sys.dont_write_bytecode` and fails if a `__pycache__` appears; the gate of real-1 verifies the cache a second time after every check that reads it (`cache untouched`). |
| 14 | real-1 review | `runner._relocate` followed a function of Pilot 7 statement by statement and was recorded nowhere. The author had counted it as his own because he retyped it. Rule 1 of section 2.1 has no exceptions, and a table cannot show the row it lacks. | `tests/pilot` A5-adapted compares our Python files with the Python files of the cached sources and fails when an unrecorded file shares more than 2 lines with them. It finds code taken over nearly as it was, not code rewritten line by line. |
| 15 | real-1 review | P1 built twice into two folders, but both builds read the same assembled kit, so a path of the kit left in a built file was the same in both and passed. The unit test planted differences in hand-made records, never in a build. | Each build now assembles the kit in its own folder. `test_build.py::test_p1_fails_when_a_built_file_depends_on_its_folder` plants absolute paths in the build processes themselves and sees P1 fail. |
| 16 | real-1 review | The trace check took `literal` and `gaps` from the same analysis that built the edges, so it could not see a reference the analysis missed; a column that read a column with a gap was recorded as complete; and the two wrong-literal tests changed one file only (the simpler cousin of lesson 9 again). | `tests/pilot` A4-unread changes every SDTM column that has no node and requires the engine to build the same ADaM. A gap is passed on to the columns that read it, in the builder and again in the check (`test_graph.py::test_a_gap_is_passed_on_to_the_columns_that_read_it`). |

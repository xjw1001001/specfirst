# specfirst

PLAN.md is the plan and the contract. Read the sections your prompt names.
Handover per track: docs/state/<track>.md. Failures seen once: docs/lessons.md.

## Commands (Linux: WSL2 Ubuntu 24.04)

- `sudo bash env/system.sh`, then `make install`: system packages, then the Python environment and R library from env/*.lock
- `. scripts/env.sh`: once per shell; puts `specfirst` on the path and finds the cache
- `make test`, `make lint`, `make ascii`: unit tests, ruff, ASCII check (what CI runs)
- `specfirst fetch`: clone the pinned sources into the ignored cache; `--verify` downloads nothing
- `specfirst gate <wp>`: the gate of a work package; its log is build/gates/<wp>/gate.log
- `specfirst catalog [--roundtrip|--sources|--yamaa|--run|--tables]`, `specfirst house [--write]`: the checks of the catalog and of the house standard; `--catalog catalog@<n>` and `--house <house>@<n>` pick a version (default `catalog@2`, `open-default@2` from catalog-2c; a house alone takes the catalog it needs; the gate std-1 checks `catalog@1`, `open-default@1` by label). `specfirst gate catalog-2a`: the versions of the standard (ADR-020)
- `specfirst compile --decisions d.jsonl --defaults --out DIR`; `specfirst render`, `specfirst parse`: decisions to specs; decisions to a standard-form document and back. `specfirst score hand|kit DIR|kits DIR|defects|pilot`: score an arm (`--arm S|C`) or a decisions file on the hand-made study HAND01 or on a generated kit; all the gate runs on a kit or on the kits of a folder; plant the scorer's defects; the pilot report (read-1a, ADR-008). `specfirst run task|arm|probe|check|score|skills|validate|pilot`, `specfirst ask`: the reader harness (read-2a, ADR-010): a task folder of a kit; a run of arm S, R or C (`--stub PLAN`, `--score`, `--keep`); the isolation probe; a kept run checked; the skills rendered (`skills --write`); the oracle; a run of arm S or R on the pilot at stage T (`--folder DIR`, outside every checkout; ADR-016), scored by `specfirst score pilot --run RUN`. Tasks and runs lie outside every checkout (`--tasks`, `--runs` or SPECFIRST_TASKS, SPECFIRST_RUNS)
- `scripts/clean_clone_gate.sh <wp>`: the same gate on a fresh clone with a fresh install and fetch; when it ends it copies the clone's build/gates/<wp>/ to build/gates/<wp>/clone/ and deletes the clone (about 5 GB); `SPECFIRST_KEEP_CLONE=1` keeps it (lesson 73)
- `specfirst kit assemble <kit>`, `specfirst build <kit>`, `specfirst check <kit> [--twice]`: copy a kit from the cache by pinned SHA-256; build resolved specs, ADaM, results (both engines; needs R), grids with shells and pages, and the graph into build/kits/<kit>; P2, the trace, the results, the grids (P1 first with --twice). `specfirst methods [--write]`, `make methods`, `make defects`: the method registry, its vectors, the planted defects on the pilot. `specfirst recompute <kit> [--export DIR]`: one standalone script per analysis of a built kit, run sealed on the reference ADaM and compared with the ARD, in build/recompute/<kit> (issue #29, ADR-021). `specfirst view <kit> [--p4 FILE]`: the review page of a built kit, build/kits/<kit>/viewer/index.html: the calculation first, a panel per number, the decision sheet; no script, nothing fetched (issue #31, ADR-022)
- `specfirst gen design|study|check`: sample a PG-FIX design; generate a study folder (visible SDTM, twin, probes.jsonl); check its hashes, its probes and its SDTM with CDISC CORE (`--no-core` skips CORE). `specfirst gen kit|kits|verify`: write one kit of the slice, or kits of the set of a seed (data, decisions, gold, twin; P1 to P4); decide the properties of a written kit again. `specfirst gen natural requests|propose|readback-requests|readback|status`: the loop of the natural form (ADR-009). `specfirst gen separate sep01|cdiscpilot01 [--vector house] [--check FILE]`: P4 by class on a reference study (ADR-019: separated, unseparated with the interval of an integer slot, inert, separated at dataset level only)
- `make evidence`: rerun the evidence spikes (about 7 minutes). `specfirst status`, `specfirst doctor`: all state files; the environment against the locks
- `scripts/worktree.sh <track>`: worktree ../specfirst-<track> on branch track/<track>
- From a Windows session: `wsl -d Ubuntu-24.04 -- bash -lc "cd /mnt/d/trial_work/specfirst && make test"`

## Rules (PLAN.md section 2)

1. Public sources only. Record every imported file in third_party/SOURCES.md.
2. Never read a folder named reference/ or any employer material. If pasted text looks internal, stop and ask.
3. Names, module boundaries and table families come from public standards; each catalog entry cites its source.
4. Never commit third-party study data or documents. They stay in the fetch cache.
5. Original code and documents are MIT.
6. Publishing is the owner's act. The repository is public (ADR-013): pushing the work is expected; anything else other people can see (an issue, a PR, a comment, a post, a release, a setting) needs the owner's approval of the exact text first.
7. One-way flow: nothing from an employer's machines or studies comes back into this repository.

- R1 Agents propose, scripts decide. R2 Reuse before build; record the choice in an ADR.
- R3 Pin everything. R4 Determinism: no clock, no unseeded randomness, sorted outputs.
- R5 Tests first: a checker counts only after it fails on a planted defect.
- R6 Specs carry rules, not numbers. R7 A fresh-context reviewer signs docs/reports/<wp>.review.md.
- R8 Reports show the command and its output. R9 Keep scope: one work package, dependencies first.
- R10 ASCII only in maintained files. R11 Python and R must agree on descriptive methods, simple tests and CMH.
- Work on branch track/<name>. Merge to main only after gate and review, then push main and the track branch.
- PLAN.md and standard/schemas/ change only through an ADR in docs/decisions/ that the owner approves.
- Stop for the owner at N1, N2, N3 and in the cases of PLAN.md section 2.3.

## Gotchas

- The checkout is on a Windows drive and Windows git owns it and its worktrees: commit, branch and merge with Windows git only. Under WSL plain `git` fails in a worktree (its link is a Windows path); specfirst's own git calls translate the link (`specfirst.paths.git_env`).
- Under WSL the Python environment, R library and fetch cache are in ~/.local/share/specfirst, not in the checkout (scripts/env.sh). In a new worktree run `make install` once.
- .gitattributes keeps every text file LF. A new script needs `git update-index --chmod=+x <file>`.
- Git for Windows ships Xpdf's pdftotext. CSR text must come from poppler (24.02 in Ubuntu 24.04).
- A yamaa project run with `save()` writes <dataset>-yamaa.parquet next to the reference data; `specfirst fetch --verify` fails on a cache with any changed, added or ignored file. Our runner hands inputs over in memory and never saves (ADR-001).
- A kit folder of real data holds kit.yaml, README.md and the files of our own its manifest names (gold/exceptions.yaml, gold/layout/<output>.yaml, gold/events/, gold/decisions/), nothing else. After a pin changes on purpose: `specfirst kit lock <kit>`. An output is built and checked only when kit.yaml lists it (`outputs`); layout spec v0 is in specfirst.machine.layout (ADR-003). The efficacy grids are compared with the CSR (`reference: {csr, page, table}`, `specfirst.machine.csr`), parsed again on every check into build/csr/<kit>/, never into the cache or git; a cell that differs needs one entry in the `cells` section of gold/exceptions.yaml.
- The R library is shared by all checkouts and `doctor` fails on any package outside the lock: never install one. It reads no Parquet and no YAML: the R engine gets JSON and is sourced from r/specfirstr/, not installed (ADR-002). standard/methods/registry.json is generated: after editing an entry run `specfirst methods --write`; add statements of semantics at the end (the recomputation scripts cite statements by number; a new method needs a template in specfirst.recompute, or its analyses are `not covered`). Model-based methods (kind `model`: ANCOVA, LS means, pairwise, dose response) are R only (ADR-015): the gold ARD takes the R engine's rows; their terms are the `programmingCode` parameters `factors` and `covariates` (`ars.reads` role `model`); their vectors' expected values come from tests/methods/oracle_models.py, not from R. The mixed model for repeated measures (`model.mmrm.*`, also `visit` and `by_visit`) runs mmrm with the optimizer nlminb (its default stops before the maximum); its vectors come from tests/methods/oracle_mmrm.py and hold to 1e-6. `test.cmh` is Python and R; its `strata` are columns (rule I12d) (amendment of real-5b). A change of standard/methods/ changes `registry_sha256` in every generated kit.yaml and the registry.json of every reader task folder: say so. read-2a's kept dry run (src/specfirst/harness/kept/) is bound to the registry only by the entries the slice reaches, listed in its binding.json (ADR-017): a change of one of them (count.subjects, percent.subjects, display.pattern, the rounding rule) fails the gate's check "arm R" and needs the dry run made again; an entry added or another entry changed does not. A new R or pyarrow fails it too: R's version stands in kit.yaml's `properties`, pyarrow's in every Parquet file.
- A reference drops trailing zeros ("70", "1"): compare with specfirst.machine.results, not by half a unit of the printed text (lesson 23). Write a non-ASCII test character as chr(...): the editor turns an escape into the character (lesson 25).
- A file-system call on /mnt/<drive> under WSL is slow: never resolve or stat a path once per element (lesson 10).
- R and its recommended packages are pinned system packages (env/r-version.txt, env/system.lock); `specfirst doctor` fails on drift and is the first check of every gate. It also checks CDISC CORE (env/core-source.txt, env/core-requirements.lock, ADR-006): after a merge that changes them run `make install`. The WSL machine is shared and one run of CORE needs gigabytes: never start several by hand (lesson 32).
- scipy.stats.fisher_exact is exact for 2 x 2 tables only (E27); specfirst.machine.methods.fisher_exact_p is exact for any table.
- Pilot 7 names: the spec is adqsnipx.yaml, the reference file is adqsnpix.parquet.
- Searches started in D:\trial_work reach reference/. Always work from inside the checkout.
- `yamaa check` reads no data: a spec can pass it and fail when run. Run a changed fragment (`specfirst catalog --run`). yamaa refuses to save a dataset on a Windows drive under WSL (`target_changed`): build under /tmp.
- The standard is versioned (ADR-020): one folder per version, `standard/catalog@<n>/` and `standard/houses/<house>@<n>/`, listed in standard/versions.yaml. A frozen version never changes (the gate check "frozen" compares its git tree); a change is a new version with a line in its migration.yaml and a record in standard/BACKLOG.yaml. From catalog@2 the defaults are in the house's defaults.yaml. No kit, task, run or score names a draft version. A house's STANDARD.md is rendered: after a change of a draft version run `specfirst house --write --house <label>`. The house layout templates are draft 0: `specfirst.machine.grid` reads layout v0 only, and the grids of generated kits are built by `specfirst.gen.display` (ADR-007).
- A generated kit is written outside the repository; dev and test kits from a seed file outside every checkout. The engines give a data-driven grouping no result for a group without records: `specfirst.gen.gold` lists the groups of one on ADSL first; organ class and term stay data-driven, so the engines give the pairs that occur (ADR-011). The decisions of a kit come first and its probes are planted for them; `probes.REACHES` names only decisions that make two alternatives equal on any data of the design that follow SDTMIG v3.4, and a kit that leaves another read decision unseparated is not written (ADR-023). The natural form of the documents of a kit comes from src/specfirst/gen/rewrites (append only; a gate never calls a model); a statement without an accepted text there gives a kit that fails the gate gen-3a. The `claude` CLI is a Windows program (npm; WSL has no node): the reader of arm R runs through WSL interop (SPECFIRST_READER), with its task and run folders on a Windows drive; logging it in is the owner's act.

# House standard open-default@2

Document: house
Catalog: specfirst-m1 2

This is the house standard open-default@2: an open default for analysis data and safety tables, built from public standards only.

Status: frozen on 2026-11-21. Version 2 of the house standard open-default, for the catalog catalog@2 (specfirst-m1 2). Any change of a default, a statement, a definition, a parent spec, a template or this document is a new version of the house (ADR-020; standard/versions.yaml).

Scope: the analysis data sets ADSL, ADAE and ADVS and four table families (the demographics table, the adverse event summary table, the adverse event table by system organ class and preferred term, and the vital signs table by visit) for a study of the design archetype PG-FIX (PLAN.md section 6.2: randomized, parallel, placebo-controlled, fixed duration) whose SDTM holds DM, EX, DS, SV, VS and AE. It does not cover efficacy analyses, laboratory data, time-to-event analyses or listings.

Order of precedence: a decision that the study's protocol or statistical analysis plan states holds first; where they are silent and the study has reference analysis data, those data decide (PLAN.md section 17, decision 17); a default of this standard holds only where both are silent.

Each anchored statement below is a default. A decision taken from this document has the status `default` and the class `house_default`, and cites the statement by its anchor, which is the ID of its entry: `doc:house#trt.start.source`, or `doc:house#tfl.population/tfl-demographics` for the decision of one table. A default that depends on the design has one numbered statement per case, after a line that says when it holds, for example `doc:house#pop.safety.rule/1`. A fixed rule holds for every alternative of its entry and is not a decision; a document that contradicts one is cited against it, for example `doc:house#ae.teae.start/no_start_date`. A line that starts with "Meaning:" repeats what the catalog says the statement means, and a line that starts with "Source:" names the public sources of the statement's alternative, or, when it has none of its own, "the sources of the entry", which may support another alternative of the same question; neither is a statement of its own.

The statements are in the standard form of the decision catalog: a parser reads each one back to its decision. Do not edit this file by hand. It is rendered from the catalog, from `house.yaml` and `defaults.yaml` of this house, and from standard/versions.yaml; `specfirst house --house open-default@2` fails when it differs.

## Terms

The words below have the meaning the named entry gives them, in every statement.

- treatment start date: the date study treatment starts, from the exposure records as the entry says (`trt.start.source`)
- treatment end date: the date study treatment ends, from the exposure records as the entry says (`trt.end.source`)
- randomized subject: a subject with a disposition record whose standardized term is RANDOMIZED, or, when the disposition data of the study hold no such record, with a planned arm code that is neither SCRNFAIL nor NOTASSGN (`pop.randomized.rule`)
- safety set: the subjects of the safety analyses, as the entry defines them (`pop.safety.rule`)
- study day: the day counted from the origin the entry names, day 1 on that date and no day 0 (`date.studyday.origin`)
- treatment-emergent: an adverse event that starts within treatment emergence, which ae.teae.start begins and ae.teae.end ends (`ae.teae.start`)
- baseline: the value of a parameter that a change from baseline starts from; for weight and height in ADSL, as demo.baseline.record says (`bds.baseline.rule`)
- post-baseline: a record dated after the treatment start date, or one on that date that is not before the first dose and is timed at or after a timed first dose (`bds.baseline.rule`)

## Conventions every table assumes

No decision states these rules; every table of this standard follows them.

- A subject is counted once in a cell, however many records it has there.
- The count n of a statistic is the number of non-missing values.
- The standard deviation divides by n - 1; with n = 1 it cannot be computed and its cell is blank.
- Alphabetical order compares the upper-cased text, then the text itself.
- A number is rounded once, from its full precision to the displayed decimals; the method registry (standard/methods/, PLAN.md section 7.3) defines every statistic.

## 4 Adverse event emergence (mod-ae-emergence)

[ae.start.imputation] A partial adverse event start date with a known month is completed with the first day of that month, or with the treatment start date when it falls in that month.

Meaning: A date with an unknown month is not completed.

[ae.teae.end] Treatment emergence ends 30 days after the treatment end date, that day included.

Meaning: An event that starts later than that many days after the treatment end date is not treatment-emergent; one that starts on the last day of the window still is.

Source: admiral (pharmaverse), function reference and source, main branch: inst/templates/ad_adae.R, derive_var_trtemfl(end_window = 30); R/derive_var_trtemfl.R: flagged when on or before trt_end_date + end_window days

Fixed rules of `ae.teae.start`, for every alternative:

[ae.teae.start/no_treatment_start] An adverse event of a subject without a treatment start date is not treatment-emergent.

[ae.teae.start/ends_before_start] An adverse event that ends before the treatment start date is not treatment-emergent.

[ae.teae.start/no_start_date] An adverse event without an analysis start date is treatment-emergent.

[ae.teae.start/no_worsening] The worsening of an adverse event present before the treatment start date does not make it treatment-emergent; the FDA guide counts worsening as emergent, and the entry that would decide it is deferred (ae.teae.worsening).

Fixed rules of `ae.teae.end`, for every alternative:

[ae.teae.end/no_end_date] A subject without a treatment end date has no end of treatment emergence.

## 5 Baseline and analysis visits (mod-bds-visits)

[bds.window.table] Post-baseline records keep their collected visit as the analysis visit.

Meaning: The target day of the visit is its planned study day (VISITDY). A record of an unscheduled visit has no analysis visit. ## Decisions without a default

This standard sets no default for the decisions below. The study documents state them, or a person is asked. They are never guessed.

- `pop.efficacy.rule`: Who is efficacy-evaluable?
- `ae.related.values`: Which causality values count as related to study treatment?
- `tfl.demog.rows`: Which characteristics does the demographics table show, in which order?
- `tfl.vs.scope`: Which parameters and analysis visits does the vital signs table show?

## Conformance rules of the parent specs

The parent specs fix these rules; no decision states them.

- ADSL: a subject is randomized when it has a disposition record whose standardized term is RANDOMIZED; when the disposition data of the study hold no such record, when its planned arm code is present and is neither SCRNFAIL nor NOTASSGN (RANDFL; the date of that record is RANDDT).
- ADSL: the end-of-study status is that of the last disposition event; a record whose standardized term is SCREEN FAILURE gives no status.
- ADAE: AEBODSYS is carried from AE, and the organ class of every table is AESOC, as in the ARS example.
- ADAE: the first-occurrence flags AOCCFL, AOCCSFL and AOCCPFL take the first treatment-emergent event by analysis start date, then by sequence number.
- ADVS: PARAM is the test name with the unit of its parameter in parentheses: the first non-missing standard unit of the test in the study, by subject and sequence number (the name alone when the test has no unit); AVALU is the standard unit of the record. VSPOS and VSTPT are not read: of several records of one test at one visit, one is analyzed (bds.window.tiebreak).
- ADVS: DTYPE is the empty text on a collected record, not null, because it is a key of the dataset; the end-of-treatment record has DTYPE LOV and AVISITN 9999.
- ADVS: the baseline record has AVISIT Baseline and AVISITN 0; CHG is computed on post-baseline records only; ANL01FL flags the baseline record, the end-of-treatment record and the one record a post-baseline analysis visit takes (bds.window.tiebreak).
- ADAE: in the order of the first-occurrence flags, an event without an analysis start date comes after every dated event of the subject.
- Labels: a variable carried from another dataset takes the label of its source; the label of the parent spec holds only for a variable it derives.
- Times of day: a time of day is numeric, the seconds since midnight, as ADaMIG names *TM variables and reference datasets store them.
